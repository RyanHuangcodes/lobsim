# DECISIONS

One line per decision, with the reason. Section numbers refer to `SPEC.md`.

## Tooling and build
- D-001 CMake comes from a project-local `.venv` (`uv pip install cmake`), not a system install: the machine had no CMake, and a local venv changes nothing outside the repo. The same venv holds pandas + matplotlib for `tools/plot.py`.
- D-002 `CMakePresets.json` defines `debug`, `release` and `sanitize` (build dirs `build/<name>`): one short, identical command per configuration for every contributor and helper.
- D-005 The presets file uses `"version": 3`, which needs CMake 3.21+: version 2 makes `generator` mandatory and we pin none. On exactly CMake 3.20 the project still builds with plain `cmake -S . -B <dir> -DCMAKE_BUILD_TYPE=...`.
- D-003 Sanitize = Debug + `-fsanitize=address,undefined -fno-sanitize-recover=undefined -fno-omit-frame-pointer`, applied globally so the dependencies are instrumented too: UBSan findings must fail the test run, not just print, and stack traces must be readable.
- D-004 `BENCHMARK_ENABLE_WERROR OFF` and third-party targets treated as SYSTEM: "zero warnings" applies to our code; a newer compiler must not break a pinned dependency.
- D-006 `LOBSIM_WERROR` (default ON) adds `-Werror` to our own targets: "zero warnings" (Section 8) is then enforced by every build instead of by reading logs.
- D-007 With no `CMAKE_BUILD_TYPE` the build defaults to Release: a bare `cmake -S . -B build` should give the fast binaries the benchmarks describe.

## Matching engine API (Section 3 is silent on exact signatures)
- D-010 Both books expose the same non-virtual member API (`submit`, `cancel`, `modify`, `best_bid`, `best_ask`, `best_level`, `depth`, `order`, `resting_orders`, `validate`) and tests are written once as typed tests over both: a virtual base would add an indirect call to the hot path for no benefit.
- D-011 `Event` is a `std::variant<Ack, Reject, Trade, Cancelled, Modified>` appended to a caller-owned `std::vector<Event>`: trivially copyable alternatives, no allocation once the buffer has grown (Section 3.7).
- D-012 `Request` is a `std::variant<NewOrder, Cancel, Modify>` with a free `apply(book, request, out)`: fuzz, replay, bench and the exchange all feed the same stream type.
- D-013 `best_level(side)` returns the best `(price, total_qty)` without allocating: the exchange needs BBO quantities after every message and `depth()` returns a vector.
- D-014 `validate()` throws `std::logic_error` naming the first broken invariant; Debug builds call it inside the book after every message: a thrown error is testable and gives a message, an `assert` does neither.
- D-015 Event hash encoding: one tag byte (Ack 0, Reject 1, Trade 2, Cancelled 3, Modified 4), then every field in declaration order, 64-bit fields as 8 bytes LE, 32-bit as 4 bytes LE, enums and bools as 1 byte: fixed and platform-independent (Section 3.7).

## Matching semantics (cases Section 3 leaves open)
- D-020 `UnknownOrder` means "not resting right now": never-assigned, fully filled and already-cancelled ids are indistinguishable to the caller, and the id index only knows resting orders.
- D-021 Cancel reason for a market order: `SelfTrade` if STP `CancelTaking` stopped it (even with zero fills), else `NoLiquidity` if nothing filled, else `IOCRemainder`. A limit IOC remainder is always `IOCRemainder`, also with zero fills: Section 3.3.3 reserves `NoLiquidity` for market orders.
- D-022 A market order whose only opposite liquidity was its own orders cancelled under `CancelResting` ends with `NoLiquidity`: nothing filled.
- D-023 Post-only "would cross" is a pure price test against the opposite best, whoever owns it: Section 3.3.5 defines it by price only.
- D-024 A modify that loses priority re-enters as a GTC taker using the order's stored `stp` and `post_only`; under `CancelTaking` a self-match on re-entry cancels the re-entering order's remainder with `Cancelled(SelfTrade)`: Section 3.3.6 says it re-enters "as a new arrival".
- D-025 Same price with a larger qty moves the order to the tail of its own level (`priority_kept = false`); it cannot match because the book is never crossed.
- D-026 `Modified.new_qty` is the requested new remaining quantity, before any matching the re-entry causes: the event is emitted first (Section 3.3.6).
- D-027 The modify `PostOnlyWouldCross` check applies only to post-only orders; a normal order modified to a crossing price trades as a taker.
- D-028 `Cancelled.qty_cancelled` is the order's remaining quantity at that moment; `Trade.aggressor_side` is the taker's side.
- D-029 FOK is valid only on limit orders (a market order must be IOC, Section 3.2), and a FOK that passes the dry run always fills completely, because execution walks the same orders the dry run counted.
- D-030 A market, limit IOC or limit GTC taker stopped by `CancelTaking` gets `Cancelled(SelfTrade)` for its remainder: Section 3.4 states it without exception, so D-021's "limit IOC remainder is always IOCRemainder" applies only when STP did not stop it. (A FOK can never end this way: it either fails the dry run or fills before reaching its own order, D-029.)

## OrderBook internals and the differential fuzz test (Phase 3; Section 3.5 is silent on these)
- D-040 `ObjectPool` keeps its free list in a separate `std::vector<void*>`, not as links inside free slots, and reserves that vector to the pool's full capacity whenever a chunk is added: a released slot is ASan-poisoned and must never be read, and `destroy()` then never allocates.
- D-041 The pool hands out the most recently released slot first (LIFO) and uses chunks of 4096 slots: the reused slot is still in cache, and one chunk of 64-byte orders (256 KiB) covers a typical book without growing.
- D-042 `ObjectPool<T>` requires a trivially destructible `T` (static_assert): the pool does not track which slots are live, so it cannot run destructors when it dies; `Order` is trivially destructible.
- D-043 A modify that loses priority returns the old `Order` node to the pool and takes a fresh one if the remainder rests (same `OrderId`, same index slot): one removal path for cancel, fill and modify, and no node that is both resting and the taker during a match.
- D-044 The id index grows (geometrically) only when an order rests; lookups bounds-check, so any id beyond it is `UnknownOrder`. `validate()` checks every resting order's own slot and compares `indexed_`, the number of non-null slots kept by the index's single writer `set_index()`, with the number of resting orders, instead of scanning the whole index: the index grows with every id ever rested, which would make a per-message `validate()` O(total ids). It also checks pool live count == resting orders (catches a leaked node).
- D-045 `OrderBook` is neither copyable nor movable: orders point at map nodes and pool slots, so a copied book would alias the original's orders.
- D-046 `ReferenceBook::validate()` finds duplicate ids by sorting a copy (O(n log n)) instead of comparing every pair: same check, fast enough to run twice per fuzz message.
- D-047 The fuzz generator uses SplitMix64 (`tests/support/splitmix64.hpp`) with rejection-sampled ranges, and never draws two random values inside one function-call argument list (unspecified evaluation order): the same seed gives the same stream on any compiler.
- D-048 `ConservationChecker::check_fast()` gives `check()`'s verdict in O(open + touched) per message by comparing the book's `resting_orders()` with the model's live count instead of re-querying every finished id. The fuzz test runs it on every message; on every 20th seed `check()` runs beside it and the verdicts must agree; `--long` uses `check_fast()` only, since `check()` is quadratic over 10^6 messages.
- D-049 The default fuzz mode is registered as 10 ctest entries of 20 seeds each, and the test presets run 10 jobs: the sanitize build takes several minutes serially.
- D-050 Adding an order to an existing price level costs one `std::map` lookup, O(log L), not the O(1) of Section 3.5's target: 3.5 also fixes the level container as `std::map`, which has no O(1) lookup by price, and an incoming order carries no pointer to its level. Only the best level is O(1) (`begin()`). L is tens of levels in the simulator, so this is a handful of comparisons; an O(1) price index is the array-ladder stretch goal of Section 10.
- D-051 `tests/unit/order_book_validate_test.cpp` also holds a deep-book differential test (8,500 resting orders, three pool chunks, scattered cancels, slot reuse, full drain) with an independent scan of the whole id index: the fuzz test keeps the book under about 500 orders, so it never leaves the first pool chunk.

## Benchmarks (Phase 4)
- D-060 The benchmark stream measures order lifetimes in new-order arrivals (exponential, mean 1,500), not in time: the bench has no clock, and this holds the book near 1,000 resting orders like the simulator's noise flow.
- D-061 `lobsim_bench` makes three passes over the same stream: timed per block of 4,096 messages (throughput), per batch of 32 (body of the distribution) and per message (far tail and maximum). On the benchmark machine the clock advances in 41 ns steps and a message takes about 21 ns, so single-message samples cannot resolve the body (Section 7: "time batches if it's significant").
- D-062 The allocation counter is on only while engine calls run, and the caller's event buffer is reserved once: every counted allocation is then the engine's own.
- D-063 Each microbenchmark times a batch of 128 operations and undoes it outside the timed region: pausing the timer per operation costs more than the operation, and the book must stay near its nominal size.
- D-064 The harness fails (non-zero exit) if its passes disagree on the event count, if an order id differs from the predicted one, or if `OrderBook` and `ReferenceBook` hashes differ on the shared prefix: a benchmark of a broken run is worse than none. The passes are compared on event counts, not on a full event hash: hashing inside the block-timed loop would add its own cost to the time being measured. The full hash is computed in the per-message pass, outside its timer pairs, and that is the one compared with `ReferenceBook`.
- D-065 `micro_bench` has two calibration benchmarks that run an empty operation in batches of 128, with and without one timer pause per batch: the difference is the timer overhead included in the per-operation times of the five benchmarks that pause, and the README reports it instead of an estimate.

## Simulator core (Phase 5)
- D-070 Every tie in the simulator is broken by one rule: the global `seq` of the event queue (events with equal time run in scheduling order); event kind and agent id never take part. Agents are created noise traders first, then the informed trader, then the market maker, so agent order fixes the `seq` of everything scheduled in `on_start`.
- D-071 Each random consumer has its own stream, seeded from `(master seed, role, index within role, purpose)`, never from the global agent index: adding a noise trader, the informed trader or the market maker leaves every other stream unchanged (tested by comparing the `NewOrder` lines of N and N+1 traders).
- D-072 `ctx.rng()` is drawn only in `on_start` and `on_wakeup`. A draw triggered by a message uses a separate stream owned by the agent: the noise trader draws each order lifetime, on the `Ack` of a limit order, from its own lifetime stream (purpose 2). Reason: whether a reply is handled before or after the agent's next wakeup depends on latency jitter, which is consumed at a rate set by every other agent; sharing the decision stream would re-phase it when an agent is added.
- D-073 One `schedule_wakeup` is one `TimerQueue` entry and each `on_wakeup` pops exactly one (`pop_due` throws if none is due): a lost or duplicate wakeup is an error, and timers add no second tie rule. Timers are never erased; an obsolete cancel timer is popped and ignored.
- D-074 `orders.log` is plain text with decimal integers only, written and read through one codec (`format_request`/`parse_request`, `format_header`/`parse_header`); enums and bools are their integer values. The replay tool of Phase 7 and the replay test use the same functions, and the test replays the parsed text, not retained `Request` objects.
- D-075 `lobsim_run` has an extra `--duration-s X` override. If the shorter run is shorter than the configured warm-up, the warm-up is set to 0 (a short run has no warm-up to keep) instead of failing validation.
- D-076 Unknown keys in the config file are errors, as are missing keys and wrong types: a typo must not be silently ignored. `informed` and `mm` are optional sections; they are parsed and validated if present, but Phase 5 creates no agent for them, so runs with and without them are identical.
- D-077 A config duration that does not fit in 63 bits of nanoseconds (or is not finite) is an error naming the field: `std::llround` of such a value is undefined behaviour.
- D-078 `-ffp-contract=off` is PUBLIC on the `sim` target: the generators and the fundamental step are inline in headers and are compiled into every user of them, so the flag must reach them too; fused multiply-adds would make floating-point results depend on the build type.
- D-079 `Simulator::add_agent(agent, latency, role, index)` lets tests add scripted agents after the configured ones; they take their streams from `StreamRole::Test` (or any role and index the test gives) and are indexed after the configured agents.
- D-080 The exchange throws `std::logic_error` if the book is ever crossed after a request, in every build type: it can only mean an engine bug.
- D-081 Each agent has one latency generator shared by its three channels (entry, response, feed), drawn at the moment a message is scheduled; the per-channel FIFO clamp is `max(sampled, last arrival on the channel)`.
- D-082 The rejection-sampling unbiasedness test uses a range of size 3 * 2^62: the modulo bias on a range of 3 values is about 2^-64 and cannot be measured, whereas on this range the lowest third would have probability 1/2 instead of 1/3 without rejection.
- D-083 `seconds_to_ns` clamps a run-time draw to 4e18 ns (and NaN to that value), and config validation bounds `duration_s` to 1e9 s and every configured duration (latency, jitter, period) to 1e18 ns, so `now + draw` stays below 2^63 for any valid run; before, a tiny `lambda` or a huge `order_lifetime_mean_s` could make the double-to-int64 cast undefined.
- D-084 The config `seed` accepts any unsigned 64-bit value, like `--seed`.
- D-085 The informed trader keeps one wakeup chain: `on_start` and every `on_wakeup` draw exactly one exponential from `ctx.rng()` and schedule the next wakeup before looking at the market, so its wakeup times never depend on prices. Its only look at the world is the last BBO it received and `Fundamental::value()`, read at wakeup. It uses plain `schedule_wakeup` (no `TimerQueue`) because it has a single kind of timer.
- D-086 The informed trader compares in ticks as doubles: buy if `V - ask >= theta` (needs an ask in the local BBO), else sell if `bid - V >= theta` (needs a bid). A one-sided BBO evaluates only the side it has; if both conditions hold (impossible with a non-crossed book and theta >= 0) the buy wins. Orders are market IOC, `STP::CancelTaking`, own `client_order_id` counter from 1; nothing rests, so `on_private` only counts events.
- D-087 The scripted `FakeCtx` moved unchanged from `sim_noise_trader_test.cpp` to `tests/support/fake_context.hpp` so the informed-trader tests share it. `Integration.FiveMinutesOfTheDefaultNoiseFlow` now expects 11 agents (10 noise traders and the informed trader); the default config's event hash changes because it now has an informed trader, while a config with no `informed` section keeps the noise-only hash ac6dbb79a513fa50.
- D-088 New optional config key `noise_traders.reference_price` (`"floor"` or `"symmetric"`, anything else is an error naming the field; `to_json` always writes it). `floor` is the rule of SPEC 5.6: buy at `floor(mid) - d`, sell at `floor(mid) + d`. `symmetric`: buy at `ceil(mid) - d`, sell at `floor(mid) + d`; it differs only when the local BBO is two-sided with an odd spread, needs no random draw, and leaves the fallbacks (last trade, initial price) unchanged.
- D-089 `configs/default.json` sets `"reference_price": "symmetric"`, the one deliberate departure from the SPEC 5.8 values. With the spec's floor rule, an odd spread lets sell limits (ref + d) improve the best ask by a tick while buy limits (ref - d) can only join the best bid; over 12 seeds of a noise-only one-hour run the final mid minus the start price was -91 to -117 ticks with floor, +97 to +121 with the mid rounded up, and -9 to +15 with the symmetric rule, a rounding artefact larger than the fundamental's one-hour standard deviation (60 ticks).
- D-090 The key is optional and defaults to `floor`, so the JSON of SPEC 5.8 keeps meaning exactly what the spec says and `simtest::default_json()` stays the spec text; the noise-only one-hour hash ac6dbb79a513fa50 is unchanged.

## Avellaneda-Stoikov market maker (Phase 6; SPEC 1, 5.6 item 3, 9 item 6)
- D-091 The quotes come from one pure function `compute_quotes(params, local BBO, q, now, end)`, tested on its own. `tau = max(0, end - now)` in seconds. Prices stay doubles until the range check, so an extreme `r` never overflows the integer conversion. "Ensure bid < ask" lowers the bid to `ask - 1`; with `delta > 0` and the two clamps it is reachable only when `r +- delta/2` rounds onto the same integer.
- D-092 Reprice by `Modify` only when a full extra quote cannot break the limit (bid: `q + quote_size <= q_max`; ask: `-q + quote_size <= q_max`), otherwise `Cancel`, and the `NewOrder` comes from the ordinary requote once the cancel's reply has arrived. Reason: a `Modify` resets the remaining quantity, so one that arrives after unseen fills refills the order; always modifying allows `q_max + 2 * quote_size - 2`, this rule bounds `|q|` by `q_max + quote_size - 1` (argument in `as_market_maker.cpp`). The stress test reaches exactly 14 with `q_max` 10 and `quote_size` 5.
- D-093 Per side the agent keeps at most one pending request and never sends another until its reply arrives: `Ack` / `Reject(New)` matched by `client_order_id`, `Modified` / `Reject(Modify)` / `Cancelled(User)` / `Reject(Cancel)` matched by kind and order id. Trades never clear a pending request. The requote runs after every BBO, every `requote_interval` wakeup and every private message; after a `PostOnlyWouldCross` reject it acts at once on the BBO it has, which may still be the stale one (then the same request is sent again and rejected again until the fresh BBO arrives); no extra back-off state was added.
- D-094 Messages that fit no state count in `anomalies()` and never crash or corrupt state: a reply with no matching pending request is ignored; a trade for an unknown order still moves the inventory (it happened); a `Cancelled` other than the reply to a pending cancel removes the order; `Reject(UnknownOrder)` for an order still believed resting (impossible: its fills arrive first) drops it; `Modified` for an order believed gone takes the exchange's word. In a correct run the counter is 0, and the tests assert that.
- D-095 The market maker draws no random numbers and keeps one wakeup chain (`on_start` schedules `requote_interval`, each `on_wakeup` schedules the next one, then requotes), with plain `schedule_wakeup` like the informed trader (D-085). It is created last, with streams (MarketMaker, 0); `Simulator::market_maker_index()` returns its index. `lobsim_run` prints its true inventory, maximum `|q|` and fills from an observer over engine `Trade` events, and its requests, rejects and anomalies from the agent's own counters.
- D-096 The stress test's aggressor sends every order with `STP::CancelResting`: with `CancelTaking` its market orders stopped at its own resting limits and the market maker was hit 9 times in 30 s; now a market order removes the aggressor's own orders in its way and reaches the quotes (about 4,800 market-maker fills per 60 s seed).
- D-097 `Integration.FiveMinutesOfTheDefaultNoiseFlow` now expects 12 agents (the market maker exists). No test pins a golden simulation hash (it depends on the platform's maths library). Instead `MarketMakerSim` checks that a run with the `mm` section differs from one without it, and `Determinism.AddingTheMarketMaker...` / `AddingTheInformedTrader...` (with the configured latencies and under 300 ms jitter) check that adding either agent leaves every noise trader's own `NewOrder` decisions unchanged.

## Metrics, output files, replay and plots (Phase 7; SPEC 5.7, 6, 9 item 7)
- D-100 Metrics come from one observer (`MetricsObserver`) that sees engine events and the true top of book with zero latency; it never schedules, sends or draws, and a test checks that attaching it leaves the event hash and `orders.log` unchanged. `lobsim_run` no longer has its own market-maker probe; it prints only what the agent alone knows (its requests, rejects, anomalies and believed inventory).
- D-101 Every metric is a function of "the state after all events with timestamp <= t" or, for the instant `warmup`, "the state after all events with timestamp < warmup" (so the window `[warmup, T]` is closed at its start and `pnl_after_warmup = pnl(T) - pnl(warmup)` counts exactly the fills with `t >= warmup`). Events at exactly T are never processed (kernel rule), so the final state is the state at T.
- D-102 Market-maker accounting: `cash` is `int64` ticks x lots (a buy subtracts `price * qty`, a sell adds it), `inventory` in lots, both from t = 0; fees are `double`, `qty * maker_fee_ticks` if the market maker was the maker else `qty * taker_fee_ticks` (a negative fee is a rebate); `pnl(t) = cash + inventory * mid(t) - fees` with `mid(t)` the last defined mid at or before `t`, and 0 for the mark if no mid has ever existed.
- D-103 The market maker's resting orders are tracked from engine events (Ack of its own `NewOrder`, Trade, Cancelled, Modified), not read from the book; "quoting" means at least one resting bid and one resting ask, and the quoted spread is its lowest ask minus its highest bid.
- D-104 Window statistics integrate state over `[max(warmup, previous event time), min(now, T))` at every state-changing hook (request, fundamental step, sample, end): time-weighted spread distribution and quoting time are exact to the nanosecond, with no sampling.
- D-105 Spread median, p90 and p99 are time-weighted quantiles on integer tick values: the smallest spread whose cumulative time reaches `p * total`. The histogram has one bin per spread 1..40 ticks (fraction of two-sided time) and one overflow bin; a spread of 0 cannot exist because the book is never crossed.
- D-106 Markouts: fill at `t`, horizon `h` -> mid in force at `t + h` (state after all events with timestamp <= `t + h`, resolved lazily when the next event with a later timestamp arrives, or at the end). A sample is skipped and counted if the mid is undefined at that instant or `t + h > T` (`t + h == T` is valid); `n + skipped` equals the number of window fills. Statistics: mean, sample sd (n - 1), 95% interval `mean +- 1.96 sd / sqrt(n)` (null for n < 2), and the quantity-weighted mean. Fills before the warm-up get markouts in `mm_fills.csv` but are not in the statistics.
- D-107 Returns: the mid is sampled at `k * sample_interval` for every k with `warmup <= k * interval <= T` (the sample at exactly T is taken at the end); a sample sees the state after every event ordered before the kernel's Sample event (time, then seq), and `bbo.csv` also has the t = 0 row. A log return exists only between two consecutive present samples; excess kurtosis is `m4 / m2^2 - 3` with central moments divided by n; autocorrelation is `sum((x_t - m)(x_{t+k} - m)) / sum((x_t - m)^2)` over pairs where both terms exist, with `m` the mean of all present values (nothing is interpolated). The returns are of a half-tick-quantised mid, so they are mostly zero or one of a few tick-sized values.
- D-108 Counts: requests by type are requests arriving at the exchange (they sum to `Exchange::requests()`); "orders sent" per role counts `NewOrder` sends by agents (some may still be in flight at T); roles follow creation order (noise traders, informed trader, market maker), and agents added by tests are `Role::Other` and not reported.
- D-109 Files: `trades.csv`, `bbo.csv` and `mm_fills.csv` write integers as integers, sides as `buy`/`sell`, roles as `maker`/`taker`, `mid` and markouts with `%.1f` (they are multiples of 0.5), fundamental and PnL with `%.6f`, an undefined value as an empty field; `summary.json` is written with `nlohmann::ordered_json` (key order fixed in the code, config echoed from `to_json`), doubles rounded through `%.6f` and null when undefined (exception: the return `mean` and `sd` use `%.6e`, six significant digits, because they are around 1e-6), two-space indent and a trailing newline. No wall-clock time, host name or path is written; elapsed time goes to stdout only.
- D-110 `replay_log` (in the `sim` library) is the one replay implementation: `lobsim_replay`, `tests/replay.cpp` and the command-line test all use it. A bad header or request line throws `ReplayError` carrying the 1-based line number; the tool prints it and exits 1. The command-line ctest `cli_run_then_replay` runs `lobsim_run --duration-s 120`, replays the log, compares the printed hash with `summary.json` and checks that a corrupted log is refused.
- D-111 `tools/plot.py` needs only pandas, matplotlib and numpy (a pandas dependency), draws the warm-up as a grey band, takes the spread histogram and the return ACF from the sampled `bbo.csv` rows (so its numbers are the sampled ones, not the time-weighted ones of `summary.json`), and exits 1 with a message if `bbo.csv` or `summary.json` is missing.
- D-112 `mid_before` of a market-maker fill is the mid in force just before the request that caused the trade was applied (captured in `on_request`; undefined when the book is one-sided at that moment, however recently a mid existed, and such a fill is left out of the decomposition, as the markout treats an undefined mid at `t + h`). It is the `mid_before` column of `mm_fills.csv`, placed before the `markout_*` columns.
- D-113 `spread_capture = mid_before - p` for a buy and `p - mid_before` for a sell (ticks per lot): what the fill earned against the pre-trade mid; the `spread_capture` block of `summary.json` covers window fills with a defined `mid_before` (n, mean, sd, 95% interval, quantity-weighted mean).
- D-114 `mid_move(h) = m(t+h) - mid_before` for a buy and `mid_before - m(t+h)` for a sell, with `m(t+h)` exactly as in the markout; negative means the price moved against the market maker (the adverse-selection number). It is computed as `markout(h) - spread_capture`, so `markout = spread_capture + mid_move` holds on every fill where all three are defined.
- D-115 Each markout's `decomposition` object is computed over window fills whose markout and `mid_before` are both defined (`n` can be smaller than the markout's `n`); on that subset `spread_capture_mean + mid_move_mean = markout_mean` up to rounding. A fill with no `mid_before` keeps its markout but is left out of the decomposition.

## Fuzzing and CI (upgrade 1; FUZZING.md)
- D-116 The spec's names match the code's: `OrderBook`, `ReferenceBook`, `NewOrder`, `Cancel`, `Modify`, `validate()`, `LOBSIM_SANITIZE`. `Request` is `std::variant<NewOrder, Cancel, Modify>`, and the books' `submit` / `cancel` / `modify` are fed through `lob::apply` (D-012). The driver lives in `lob::fuzz` (`fuzz/diff_driver.{hpp,cpp}`), with `kFuzzMaxPrice` = 1000.
- D-117 `decode()` resolves Cancel/Modify targets with a private `ReferenceBook`, not an `OrderBook`: both books give the same ids up to the first mismatch, a crash file must still decode when the fast book faults, and the injected-bug macros of a later phase never touch the reference. `run_diff()` does not call `decode()`; it decodes record by record with `decode_record` and takes `known_ids` from the live Acks of the fast book (SPEC 3.1), so the byte-to-request mapping has one source.
- D-118 Beyond the event buffers and `validate()` (SPEC 3.2), `run_diff` compares `depth(Buy/Sell, SIZE_MAX)` and `resting_orders()` after every request, and `order(target)` of the two books after every Cancel/Modify, so a state difference shows on the request that causes it rather than at a later event.
- D-119 Every `apply()` and `validate()` call in `run_diff` is wrapped in `try/catch (const std::exception&)`: in a non-NDEBUG build the books call `validate()` themselves and throw `std::logic_error` from inside `submit/cancel/modify`, and an exception leaving `run_diff` would reach `std::terminate` before the report is printed. The report names the book and `e.what()`, then `std::abort()`. `decode()` ignores such a throw from the reference book so a crash file still decodes.
- D-120 The regression test (`tests/fuzz_regressions.cpp`, `fuzz_regression_tests`) lists `fuzz/regressions/diff/` then `fuzz/corpus/diff/` when it runs (non-recursive, regular files, names starting with '.' skipped so `.gitkeep` can hold an empty directory, sorted by name) and is registered with a plain `add_test(NAME fuzz_regressions_diff ...)`. `gtest_discover_tests` is not used: its list is cached at build time and would silently skip a file added later. Parameter names are the sanitized file name with a `regressions_` / `corpus_` prefix, made unique with `_2`, `_3`. ## Book-builder operations (upgrade 2, R1)
- D-151 Both books gain four mutating or previewing operations and one query, with the same API and semantics: `insert_passive`, `reduce`, `remove`, `preview_match`, `level_orders`. They exist so that a feed replayer can place and take away orders without matching, because the exchange has already matched. `submit`, `cancel` and `modify` are unchanged. Types, in `lob/types.hpp`: `enum class Status { Ok, WouldCross, UnknownOrder, Oversized, InvalidQty, InvalidPrice }` (with `to_string`), `Result<T>{Status status; T value; ok()}` (value-initialised, so `0` for an id on failure) and `Fill{maker_id, price, qty}`. All have `operator==`, because the differential fuzzer compares them exactly. None of the operations emits events: a replayer knows what it asked for.
- D-152 `insert_passive` takes its OrderId from the same counter `submit` uses (`next_order_id_`), exactly as an Acked `NewOrder` does, so ids stay dense and the id-indexed vector of the fast book stays small; an exchange order id is never used as an engine id. Validation order is that of `NewOrder` (SPEC 3.2, first failing check wins: quantity, then price range; there is no flags check here) followed by `WouldCross` (a buy at a price >= the best ask, a sell at a price <= the best bid, as for post-only). On any failure nothing changes and no id is consumed. The order is a plain GTC limit: `stp = CancelTaking`, `post_only = false`; `owner` defaults to 0 (no simulated agent has owner 0). It lands at the tail of its level (`ReferenceBook`: the next `priority_seq`).
- D-153 `reduce(id, qty)`: `qty <= 0` is `InvalidQty` (checked before the id lookup); an id that is not resting is `UnknownOrder`; `qty == remaining` removes the order (`Ok`); `qty > remaining` also removes it and returns `Oversized` (the replayer counts such messages; the order cannot be left behind with a quantity the feed says is gone); `qty < remaining` reduces in place and keeps the queue position and the level's total. `remove(id)` is `Ok` or `UnknownOrder`. In a non-`NDEBUG` build `insert_passive`, `reduce` and `remove` call `validate()` at the end, like `submit`, `cancel` and `modify`.
- D-154 `preview_match(taker_side, limit, qty)` is a const walk of the opposite side, best price first and first in first out inside a level. It stops when the next level is worse than `limit` (a buy: level price > limit; a sell: level price < limit) or `qty` is filled. It returns one `Fill` per touched order, with the quantity taken from it (the last may be partial) and the level's price. It does not look at owners (no self-trade prevention) and changes nothing. `qty <= 0` gives an empty list. The `limit` is not range-checked: a limit outside `[1, max_price]` simply admits all or no levels.
- D-155 `level_orders(side, price)` returns the resting `OrderView`s at one price on one side in priority order, empty if there is no such level. It is on both books, and fuzzed against the reference, because the replayer needs it to resynchronise a level against the feed and to attribute a seed order to its place in the queue, and because it is the only query that exposes the queue order of a level: depth sums quantities, and `order(id)` shows one order. In the reference book it is a filter by side and price sorted by `priority_seq`; in the fast book it is a walk of the level's list.
- D-156 The fuzz target `fuzz_diff_builder` (`run_diff_builder`, corpus `fuzz/corpus/diff_builder/`, regressions `fuzz/regressions/diff_builder/`) uses the 8-byte records of `fuzz_diff` with `kind = b0 % 7`: 0 to 2 decode through the same code as `fuzz_diff` (`decode_fields`; the 19 seeds of `fuzz/corpus/diff` decode to the same text as before), 3 is `insert_passive` (side bit 0 of `b2`, price, qty and owner by the shared rules), 4 is `reduce`, 5 is `remove` (the target by the shared rule), 6 is `preview_match` (the price is the limit). `known_ids` holds every Ack and every successful `insert_passive` id, in order. After each operation the return values (status, new id, fill list) and the event buffers must be equal; then the post-request checks of `run_diff` run, plus `level_orders` of both books for the levels the operation touched, found in the reference book before the operation (a New: its side and price; an insert: its side and price; reduce, remove, cancel: the target's level; a modify: the target's level and the new price on its side; a preview: the best level of the side it walks). The C++ names are `BuilderOp`, `decode_builder_record`, `decode_builder` and `op_to_string` (not an overload of `to_string`, which would be ambiguous for `NewOrder`, `Cancel` and `Modify`, since each converts to both variants). `lobsim_fuzz_decode --builder <file>` decodes such an input. `make_seeds.py` now writes both corpora by default and has `--out-builder` and `--check-builder`; `fuzz_seeds_up_to_date` checks both. The 11 named seeds (`insert_passive_basic`, `insert_passive_would_cross`, `insert_passive_at_tail`, `reduce_partial`, `reduce_exact`, `reduce_oversized`, `reduce_unknown`, `remove_basic`, `preview_across_levels`, `builder_mixed`, `mixed_builder_stream_64`; the stream is SplitMix64 seed 2) are required by `FuzzCorpus.CommittedSeedsAreFound`; the suite `DiffBuilder` (ctest `fuzz_regressions_diff_builder`) runs every file of the two folders.

- D-160 Time is parsed as text: integer seconds (digits only, `from_chars` into `uint64_t`, so overflow is detected) times 10^9 plus the fraction padded on the right to 9 digits. The check for types 1 to 5 is unchanged (size > 0; price > 0 for types 1 to 4; a type 5 hidden execution may carry price 0).
- D-162 One trailing `'\r'` is removed before a line is split (a file with CRLF line ends), and `Parsed::cr_stripped` records it; a second `'\r'` stays in the last field and the line is rejected as non-numeric. Fields are integers only: an empty field, a leading `+`, a space or a decimal point is rejected; a leading `-` is accepted where the value may be negative.
- D-163 Orderbook rows: exactly `4 * L` fields, per level the ask price, ask size, bid price, bid size. Size 0 is an empty level whatever its price. The exact placeholder LOBSTER writes for an empty level could not be verified (the sample README was not available); the seeds use `9999999999` / `-9999999999` with size 0 because it is the commonly reported convention, and the parser does not depend on it. ## LOBSTER replayer (upgrade 2, R3)
- D-168 The replayer is in the `replay` library (`include/replay/replayer.hpp`; `src/replay/replayer.cpp` replays, `src/replay/replayer_match.cpp` runs the matching check, `src/replay/replayer_json.cpp` and `src/replay/replayer_text.cpp` write the reports; several files for the reason of D-158 and D-186). `Replayer(levels, ReplayOptions{mode, compare_depth, trust_depth, max_lookahead})` and `run(messages, orderbook)` stream both files line by line through a small reader that keeps a deque of parsed lines ahead of the current one, for the burst lookahead of the matching check; more than `max_lookahead` (100,000) buffered lines is an `InputError`, never unbounded buffering. `replay_files(messages_path, orderbook_path, options)` opens the files and takes `L` from the orderbook file name. The book is `lob::OrderBook` with `max_price = 2'000'000'000`, prices in LOBSTER units. The replayer keeps the depth to which the previous row was exact before any correction, for the trust rule of the matching check.
- D-169 Lines are numbered from 1, the same number in both files: line k of the orderbook file is the book after line k of the message file (the spec's "row 0" is line 1). Every line is compared with the oracle, line 1 included (after seeding it is exact unless the book refused part of the seed); `rows_compared` is the denominator of every exact-row rate.
- D-170 Message handling beyond the spec's table. A known id whose Direction is not the order's side (`direction_mismatch`, checked for types 2, 3 and 4, not only 4) or whose price is not the order's price (`price_mismatch`) is skipped and the book is left unchanged: the id then names an order that disagrees with the message. Direction is checked first, and a message is counted once. A type 3 whose size is not the remaining is still deleted and counted `delete_size_mismatch` (spec 4.1). `oversized_reduce` is counted for type 2 as well as type 4 (`reduce` removes the order either way, D-153). A type 1 above `max_price` is `submit_bad_price`. Seed attribution of a type 3 reduces the synthetic order by the message size. Every message lands in exactly one outcome counter (`parse_rejected`, `consumed_by_seed`, `submitted`, `dup_id`, `submit_would_cross`, `submit_bad_price`, `cancelled`, `deleted`, `executed`, `direction_mismatch`, `price_mismatch`, `seed_attributed`, `unknown_id`, `hidden_exec`, `cross_trade`, `halt`); the fixture test checks that these sum to `messages`. `seed_orders` and `seed_rejected` count the synthetic orders placed from line 1.
- D-171 Bad input. A message line that does not parse is counted `parse_rejected` and skipped; its orderbook line is still compared. An orderbook line that does not parse (after line 1) is counted `oracle_rejected` and not compared, the trust depth falls to 0, and strict mode stops there (exit 2). Fatal (`InputError`, exit 1): a file that cannot be read, an orderbook file name without `_orderbook_<L>.csv`, a message file name whose `L` differs, a line 1 whose column count is not `4 L` or that does not parse (the opening book is seeded from it), and files with different line counts (found when the first one ends).
- D-172 The resync window of a side is every price at least as good as the oracle's L-th level, or the whole side when the oracle shows fewer than L levels. The spec's "from the best price to its L-th price" read literally would leave a stale level that is better than the oracle's best untouched forever; the touch is always published, so such a level is removed (at its rank, 1 when it is our best). The exporter's `--filter-window` uses the same window. Removals on both sides come first, then the size corrections, so a synthetic insert never meets a level that is about to go. `corrected_by_level[d]` counts levels fixed (one per row and level); a synthetic insert the book refuses (only possible with a crossed oracle row) is counted `resync.failed` too. Removed levels of rank above L are counted `removed_beyond_level_l`. A malformed oracle row (D-164) is never used to correct (`resync.skipped_malformed`). Resync runs only on rows not exact at depth L; a row exact at L leaves nothing to correct.
- D-173 `crossed_state` is counted as the spec says, but with `lob::OrderBook` it is always 0: `insert_passive` refuses a crossing order (counted `submit_would_cross`) and `validate()` rejects a crossed book. `submit_would_cross` is where an uncorrected drift shows up instead.
- D-174 Outputs. `summary.json`: mode, levels, compare and trust depth, `completed`, `strict_failure_line`, `lines`, `rows_compared`, `counters` (all of the above, plus `messages`, `type_1`..`type_7`, `time_truncated`, `oracle_malformed`, `oracle_rejected`, `crossed_state`), `exact_rows` (per depth: `exact`, `rows` and a `percent` string), `divergent_rows`, `resync` (`rows`, `corrected_by_level`, `removed_by_rank`, `removed_beyond_level_l`, `failed`, `skipped_malformed`), then `wall_ns` and `messages_per_second`; everything but the last two is deterministic, and that part is what the fixture test compares. Percentages are integer arithmetic, cut (not rounded) to two decimals. `divergences.csv` (`line,depth,side,ours_price,ours_size,oracle_price,oracle_size`): the first 1,000 rows not exact at depth L, one line per side that differs at the first differing depth; a level the book does not have is written with an empty price and size 0, the oracle's level as given. On stdout: the one-screen summary with the interpretation rule, and for a strict failure the line, both books side by side and the last 20 message lines.
- D-175 `lobsim_lobster` exit codes: 0 done, 1 bad arguments or input that cannot be replayed, 2 strict failure. `--compare-depth` must be in 1..L; `--trust-depth` must be at least 1 (it has no upper bound here: the matching check reads it).

## Matching agreement (upgrade 2, R6)
- D-180 Bursts. The replayer starts a burst at a parsed type-4 message that is not already part of one, and collects the rest through the reader's capped lookahead: the following lines while each parses, is type 4, and has the same time and Direction (a line that does not parse ends the burst, as any other type does). The check runs before the burst's first message is applied; the messages are then applied one at a time as before, with an oracle comparison after each. Line 1 is consumed by the seed and never part of a burst; if executions continue it, the burst starts at line 2. Strict mode may stop inside a burst. The 100,000-line lookahead cap (D-168) also covers the 5 lines read after a burst for an example.
- D-181 The two sides of the comparison. Data: each message, in order, as the replay will apply it, without changing the book. A known id whose order still has quantity left after what earlier messages of the burst take is `(external id, message price, size)`; a message that will be skipped (Direction or price disagreeing with the order, D-170) takes nothing. Otherwise the message goes through seed attribution as in 4.3, on what the earlier messages left of each synthetic order, and is `SYN@price`; if no synthetic order fits, the burst is `excluded_unknown`. Prediction: `preview_match(opposite of Direction, worst price of the burst, sum of sizes)`, with makers mapped back to external ids; a synthetic maker (or one without an external id) is `SYN@price`. Fills are written `<id> <size> @ <price>` or `SYN@<price> <size> @ <price>`.
- D-182 Classes, in this order: `excluded_unknown` (the same at every trust depth); `excluded_untrusted` when the previous row was not exact before correction down to T or T < distinct prices + 1; otherwise the comparison. Equal fills with no synthetic fill on either side are `exact`; equal when a synthetic fill matches a synthetic fill at the same price and size are `exact_via_synthetic` (a synthetic and a real id never match). Otherwise the first differing fill decides: a different price is `price_skip`, the same price with a different order `queue_order`, the same order and price with a different size `size_split`; if every fill both lists have is equal, `length`. `price_skip` is split into `price_skip_better` (the prediction is at a better price for the taker: lower for a buyer, higher for a seller; this is the spec's definition) and `price_skip_worse` (the data filled at a price where the book had less: lobsim's walk went on to a worse price). Both count as `price_skip`, so every burst has exactly one class. `first_difference` is 1-based; for `length` it is the shorter list's length + 1.
- D-183 Trust depths and output. The counts are computed in one pass for each of the distinct depths among 1, 3, L and `--trust-depth` (default 3, the headline), in ascending order; a depth above L can never be trusted. Agreement = (`exact` + `exact_via_synthetic`) / (bursts − both exclusions), always printed as numerator / denominator with every exclusion count. `summary.json` has a `matching` block: `bursts`, `burst_messages`, `headline_trust_depth`, `by_trust_depth` (per depth: the eight class counts, the two price-skip counts, `numerator`, `denominator`, `percent`) and `examples`: the first 3 bursts of each mismatch class at the headline depth, each with its first line, `first_difference`, `price_skip` (better or worse, price-skip examples only), the burst's lines, both fill lists, and up to 5 lines before and after. Strings are JSON-escaped (example lines come from the input). The check runs in every mode. Its code is in `src/replay/replayer_match.cpp`.
- D-184 Tests. New fixture `tests/fixtures/lobster/matching` (27 lines, every row exact) with one burst per class; the expected summary, including the examples, was derived by hand. The `MatchingClass.*` tests replay it up to the end of one burst and check that exactly the expected counters went up against the previous burst's end; `excluded_untrusted` is also checked on the resync fixture, where the previous row was not exact. The existing fixtures' matching blocks were derived by hand too. `basic_types` has a `queue_order` at line 11: the hand-written data executes order 22 while the opening seed is ahead of it in the queue, so it stays as written, as an example of that class. `MatchingBurst.TheLookaheadIsCapped` checks the cap. The unfiltered closed loop now also requires, at trust depth 3, agreement of every scored burst, at least one scored burst, and zero `queue_order`, `price_skip`, `size_split`, `length` and `excluded_unknown`. Measured: the 60 s run of the test has 370 bursts, 370/370 at T = 3 and T = 10 (369/369 filtered at T = 10); 600 s runs of the default config, unfiltered, strict at depth 10: seed 7 has 4,994/4,994 at T = 3 (2 bursts of 3 or more prices excluded), seed 11 4,645/4,645 (4,642 exact, 3 via a synthetic order, 5 excluded).

With the matching check's reports the D-158 linker failure came back on the macOS fuzz build (`ld: invalid r_symbolnum=1 in '../libreplay.a(replayer_report.cpp.o)'`, then on `replayer_json.cpp.o` after a split): Apple `ld` reads every member of the archive, so all four fuzz targets failed to link although none uses the replayer. The one runtime dependency, uPlot, is vendored and pinned (D-204), loaded as its IIFE global from `web/vendor/uplot/`; `app.js` reads `window.uPlot` rather than importing it as a module. This keeps the dashboard deployable as static files with no registry/CDN fetch at view time and lets the pure modules be unit-tested under `node --test`.
- D-208 Palette and ramp used verbatim. The exact validated hexes from the spec are used as CSS variables for both light and dark themes (buy/best-bid, sell/best-ask, MM quotes, surfaces, inks, gridlines); none are altered. The heatmap is a single-hue blue log ramp built from the spec's step hexes into a 256-entry RGBA lookup table (one entry per u8 code), reversed between light and dark. Lines are 2px, gridlines are solid hairlines (never dashed), trade dots are area-scaled by quantity with a cap, and there are no dual y-axes on any chart.
- D-209 No fourth series colour; MM quotes carry text labels. The palette defines only three data colours (buy, sell, MM quotes), so no fourth colour is introduced for additional series. The MM bid/ask resting quotes on the ladder are identified by the text labels `MM bid` / `MM ask` (and appear by name in the table view), not by colour alone, so colour is never the only cue.
- D-210 Time lookups are binary search. Every cursor/scrub/playback time lookup uses `binarySearchTime` over the sorted time arrays (`web/js/search.js`), returning the sample at or just before the target. No panel does a linear scan per frame.
- D-211 Heatmap pre-rendered once per zoom level. The heatmap is rendered one RGBA lookup per code into an offscreen canvas `ImageData` (index `col*rows+row`) once per zoom level and then blitted each frame; it is re-rendered only on a zoom change or a light/dark theme swap. Best-bid/best-ask overlay lines and trade dots are drawn on top of the blit. Playback advances the cursor via `requestAnimationFrame` and only re-blits the cached buffer plus overlays, never re-decoding or redrawing cells.
- D-212 Decode facts the JS relies on (from `viz/viz_core.cpp`, documented in `viz/BUNDLE.md`). `trade_aggressor` is i32 with `0 = buy`, `1 = sell` (tooltips and tables show the word, not a colour). The heatmap is stored outer-loop over time columns, inner-loop price from `price_hi` down to `price_lo`, so byte index `= col*rows + row`, row 0 is the highest price (`price = price_hi - row`), and column `k` time `= t0_ns + k*dt_ns`. Missing i32 is `-2147483648` (INT32_MIN); missing f64 is `NaN`. The legend decodes code to real lot size via the inverse log using the stored `v_max`.
- D-213 No-MM hide behaviour. When `config.mm` is null the MM i32 series (`mm_bid`, `mm_ask`, `mm_inventory`) are all `missing_i32` and `mm_cash`/`mm_pnl` are `NaN`; `hasMM(meta)` detects this and the dashboard hides the MM-dependent panels (the MM quote lines on the price chart, the inventory chart, and the PnL chart) and the ladder's `MM bid` / `MM ask` marks, degrading gracefully.
- D-214 Test fixture approach. The viz tests use one small committed bundle fixture (under `web/test/fixtures/`, kept under 50 KB), regenerated by `scripts/make_viz_fixture.sh`. A C++ end-to-end ctest fails if the committed fixture's `meta.json` `schema_version` does not equal `viz_core.cpp`'s `kSchemaVersion` (1), catching a stale fixture after a schema change. The node bundle tests (`web/test/`) run via `node --test` against the pure modules; the ctest entry that drives them **skips** cleanly when `node` is absent rather than failing. `site/` and `viz-out/` are gitignored and never committed.
- D-215 Pages workflow action versions. `.github/workflows/pages.yml` pins the newest major tags verified against each action's latest release: `actions/checkout@v7`, `actions/configure-pages@v6`, `actions/upload-pages-artifact@v5`, and `actions/deploy-pages@v5`. The build job runs `scripts/build_site.sh` (so CI and local stay in sync), uploads `site` as the Pages artifact, and the deploy job (`needs: build`, environment `github-pages`, permissions `pages: write` + `id-token: write`) runs `deploy-pages`. `ci.yml` is untouched.
- D-216 actionlint still could not run (confirms D-205). In this sandbox the npm registry, the Go module proxy, and the GitHub release-asset download all return HTTP 403, so `actionlint` could not be installed by any route. `pages.yml` was hand-verified instead: the `on:` triggers, the two jobs with `deploy` needing `build`, the top-level and deploy-job permissions, the `environment.url` referencing the existing `deployment` step id, the `path: site` matching the uploaded artifact, and all four action `@vN` refs confirmed to exist as tags. Indentation and style match the untouched `ci.yml`.
- D-217 Performance budget: method. A true headless browser first render could not be measured (the sandbox's Chromium is network-isolated from the sandbox localhost and `file://` is blocked). First render was instead measured by instrumenting the two dominant stages of the load-to-first-render path with `performance.now()` in node, running the actual shipped modules (`bundle.loadBundle` + `heatmap.buildRampLUT` + `heatmap.prerenderHeatmap`) against a real default-config 1-hour bundle (`lobsim_run --duration-s 3600` then `lobsim_viz_export`). The remaining first-render cost (three uPlot chart builds plus one scaled blit) is extrapolated from typical uPlot build times, with a generous margin; this is the stated assumption.
- D-218 Performance budget: numbers. Target: first render of a 1-hour bundle under 2 s. For the 1-hour bundle (heatmap 117 rows x 14400 cols, `data.bin` ~6.75 MB, ladder_count ~36000, ~65k trades), averaged over 10 iterations: typed-array decode 0.047 ms, build the 256-entry RGBA LUT 0.212 ms, full-resolution offscreen heatmap pre-render 8.33 ms; sum ~8.6 ms. For the 2-minute bundle (74 x 480): decode 0.015 ms, LUT 0.049 ms, prerender 0.205 ms; sum ~0.27 ms. The heatmap pre-render (1.68M cells) is the single most expensive first-render step and completes in ~8.6 ms, leaving order-of-magnitude headroom under the 2 s budget even after allowing a 10-20x margin for uPlot + DOM + layout + blit. Playback re-blits the cached offscreen buffer and redraws only overlays each frame (no per-cell redraw, no re-decode), sustaining 60 fps.

## The fake day (upgrade 2b, D3)
- D-224 `lobsim_export_lobster --lobster-like` (`--window-start-s` default 300, `--hidden-rate` default 0.2, `--halt-at-s` default halfway, `--seed` default 20120621) switches on all the LOBSTER quirks together and `--filter-window` with them. The default export is untouched: same files, same stdout. The window is from the start second to the time of the last request (a first pass over `orders.log` finds it); `--halt-at-s` is on the same simulated clock as `--window-start-s` and, like it, a whole number of seconds (the default halfway point is exact to the nanosecond and is printed in `README_SYNTHETIC.txt`). Messages before the window update the mirror book but are not written and are counted separately (`messages_before_window`), not as "filtered".
- D-225 Hidden executions: a Poisson stream drawn with the project's `Xoshiro256StarStar` (stream seeded by `--seed`). Gap = `exponential(rate)` truncated to whole nanoseconds, the only floating point and never written to a file. Per event, size (1-100) and direction are drawn first, then the price is `uniform_int(best bid, best ask)` of the true book; if the book is not two-sided the draw is skipped and counted (0 in both fake days). Ids are 2^40 + k; the export fails if a simulator order id ever reaches 2^40. Injected messages at the same instant as real ones go after them (the pending stream is flushed only up to `request time - 1 ns` before a request); a hidden execution and the halt at the same instant: hidden first. Rows of injected messages repeat the last written row (the current true book if none was written yet).
- D-226 Empty levels are `0,0` (price, size) in `--lobster-like` rows only; the default export keeps +-9999999999. The halt is type 7, price -1, size 0, id 0, direction 1 (our stand-in encoding). Output into a directory whose normalized path ends in `data/lobster` is refused with exit 1 before anything is created. `README_SYNTHETIC.txt` and `<ticker>_injected.json` are written next to the files; the json is what tests compare with the replay's `hidden_exec` and `halt` counters.
- D-227 `SYNTHA`: `configs/default.json`, run seed 20120621, hidden-stream seed 101. `SYNTHB`: `configs/synthb.json` = default with `informed.lambda` 2.0 -> 8.0 (x4) and `noise_traders.lambda` 5.0 -> 10.0 (x2, per trader, 10 traders), run seed 20120622, hidden-stream seed 202. Each runs 300 s of warm-up plus 3600 s of window, L = 10, via `scripts/make_fake_day.sh` into `data/synthetic/` (git-ignored). Test `lobster_like_fake_day` (60 s warm-up, 120 s window, seed 11): two exports byte-identical, the guard refuses `data/lobster`, and the replay in resync mode counts exactly the injected hidden executions and one halt, with `unknown_id + seed_attributed > 0`. The exponential draw uses `std::log`, so a different libm could in principle move a gap by a nanosecond; the fake days are checked by hash on one machine and by the count test everywhere.

## Calibration (upgrade 3)
- D-300 One calibration-file contract, `include/calib/calibration.hpp` (`calib::Calibration`), shared by the estimator that writes it, the calibrated background flow that reads it, and the hand-made recovery truth. Every per-side array is indexed 0 = buy, 1 = sell; distributions are sparse integer PMFs (`values` strictly increasing, positive `counts`), so placement distances, sizes and spreads all use one type and one pair of distances (`total_variation`, `wasserstein1`). Aggressive orders are counted by the aggressor's side, the opposite of the LOBSTER Direction of their type-4 rows. The median mid is stored as the floor of the median in ticks, because the simulator's start price is a whole tick. `source` ("real", "synthetic", "hand-made") travels with every number derived from the file.

## Calibration (upgrade 3), C1: the estimator
- D-301 Replay observer hook (`include/replay/replayer.hpp`). `ReplayObserver` has `on_message(const ObservedMessage&)` and `on_end(const RunEnd&)`. `ObservedMessage` holds the line number, the parsed message (`nullptr` when the line does not parse), `before` and `after` as `PublishedRow`s, and the burst grouping of the matching check (`burst_size`, `burst_position`; 0 for every message that is not type 4 and for line 1, which the seed consumes, D-180). A `PublishedRow` is the orderbook row (the true book, never `Replayer::book()`, which can be wrong after unknown ids or filtered messages), its `malformed` flag, and the published window bounds `ask_bound`/`bid_bound`: the L-th level's price on a side that shows all L levels, nullopt otherwise (the resync window of D-172; none on a malformed row). `published_row(const Parsed<BookRow>&)` is public. `Replayer::observe(observer, from_ns)`, `Replayer::stop_before(time_ns)` and `Replayer::run_end()` (reason `EndOfInput`, `TimeBound` or `StrictFailure`, lines replayed, and the bound line and its time) are setters, not `ReplayOptions` fields: the existing tests aggregate-initialise all four fields of `ReplayOptions`, and a fifth would draw `-Wmissing-field-initializers`. Without them `run()` takes the same path as before; every replay fixture's `summary.json` is unchanged, and `ReplayObserver.ObservingDoesNotChangeTheReplay` checks that attaching an observer changes nothing either. Pointers in an `ObservedMessage` are valid during the call only.
- D-302 The time bound. The reader parses each message line before taking it; the first line that parses with a time at or after the bound is read (to see the bound) and is not replayed, compared, counted or observed, and nothing after it is read: the reader ends there, so the burst lookahead (a burst shares one time) and the five context lines of a burst example stop there too. A line that does not parse cannot end the replay, its time being unknown; it is observed as unparsed and the estimator takes nothing from it. Test `ReplayObserver.TheTimeBoundStopsBeforeTheFirstMessageAtOrAfterIt` gives an orderbook text that ends at the bound line: reading one more line would be an `InputError`. The estimator's first pass over the message file (D-304) stops at the same line, so with a given window nothing at or after its end is read but that one line; `Window.NothingAtOrAfterTheWindowEndIsReadBeyondTheBoundLine` runs the estimator on streams that end right after the bound line and fail any read beyond it (once with a burst whose lookahead meets the bound). The SHA-256 of the inputs covers the whole files: that is provenance of the files used, and no statistic comes from it.
- D-303 Lines before `--from` are replayed but not observed. The replay starts at line 1 and seeds from row 1 as always, so its book and counters are those of a plain replay; observing starts at the first message line that parses with a time at or after `--from`, and from there on every line is observed, the first one with the row before it as `before`. Rejected: skipping them, which would need a second seeding path (from the row before `--from`) in the replayer for no gain, since the estimator reads only published rows.
- D-304 The window. `--from`/`--to` are whole seconds after midnight in `lobsim_calibrate` (0 to 86,400) and nanoseconds in the API; a bound left out takes its default (36,000 and 55,800 s). A first pass over the message file, stopping at the first message at or after the window end as the replay does (D-302), finds the first message time, the last one before that end, whether the data goes past it, and the GCD of the type-1 prices (D-305). The default window is covered when the first message is at or before 36,000 s and some message is at or after 55,800 s; when neither bound is given and it is not covered, the file is read to its end (no window was asked for, so there is no later period to keep unread) and the window is the data's whole span `[first, last + 1 ns)`, which `window_note` says (the fake days: 34200.0017 to 37799.98 s). A given window is clipped to the data as far as it was read (its end only when the file ends inside it), also noted; an empty result is an error (exit 1). `observed_ns` is the length of the effective window. The output name uses the window in whole seconds, from rounded down and to rounded up (`SYNTHA_2012-06-21_34200-37800`).
- D-305 Tick. `auto` takes the GCD of the type-1 prices of the effective window (from the pre-pass): a multiple of 100 gives 100, anything else the GCD with a warning on stderr and in `report.warnings` (the fake days give 1, as the spec expects); no type-1 message in the window is an error. A type-1 price not divisible by the tick is `subpenny`: excluded from the rates, the sizes, the placement and the lifetimes, and later messages naming it are counted as messages to an excluded order. Under `auto` this cannot happen (the tick divides every type-1 price of the window), so it needs `--tick-units N`. A best quote off the grid in the row before an order (a subpenny order resting at the touch) excludes that order's placement as `best_quote_off_tick`.
- D-306 Placement. Delta and the spread come from the row before the message, on the order's side, in ticks. Exclusions, each counted in `report.placement.excluded`: `no_previous_row` (line 1), `previous_row_unparsed`, `previous_row_malformed`, `one_sided_previous_row`, `best_quote_off_tick`, `crossed_previous_row`, `would_cross` (Delta below -(s-1)). An order excluded here is still a submission: it counts in lambda_L and in the limit-size PMF, but has no lifetime (its distance bucket is unknown).
- D-307 Rates. lambda_L counts the type-1 messages of the window by Direction (subpenny ones excluded, D-305). lambda_M counts bursts as the replayer groups them (D-301), by the aggressor's side, the opposite of Direction; a type-4 message on line 1 belongs to no burst (the seed consumes it) and is counted, not rated. Type 5 (hidden executions), 6 and 7 are counted only. Each rate is count / observed seconds.
- D-308 Sizes. The limit-size samples are the type-1 sizes behind lambda_L; an aggressive size is the sum of a burst's sizes (overflow-checked; an overflow is counted and left out). The 99.9th percentile is by nearest rank: the value at rank n - floor(n / 1000) = ceil(0.999 n) of the n sorted samples (integer arithmetic); every sample above it is counted in its bin, and `pooled_*` and `report.sizes` give how many moved.
- D-309 Lifetimes. A type-1 message of the window with a placement Delta starts a lifetime, keyed by order id, in `distance_bucket(Delta)`. A type 3 naming it is the event (a size other than the remaining is counted, still an event). A type 2 reduces it and never ends it, except that one taking the remaining to zero or below is counted (`partial_cancel_to_zero`) and is the event, since nothing is left. A type 4 reduces it; reaching zero censors it as executed (an oversized one is counted). A message whose Direction or price disagrees with the order is ignored and counted. A cancellation in the submission's own nanosecond is set to 1 ns and counted (the file needs positive times; 0 on both fake days). A type 1 for an id still tracked is counted and keeps the first order's lifetime; an id reused after its order ended is counted and starts a new one.
- D-310 Leaving the published window. After each observed line, on its row (`after`), every tracked buy below `bid_bound` and every tracked sell above `ask_bound` is censored at that line's time; a side without a bound (fewer than L levels shown) censors nothing. The order's own submission row counts, so an order submitted outside the window (possible in unfiltered data) is censored at 0. Rows that do not parse or are malformed are not checked, and counted. The tracked orders sit in an ordered set of (price, id) per side, so a row costs a lookup plus one step per censored order. The ids of censored orders are kept: their later messages are counted `after_censoring` by type, never as events or unknown ids. Orders alive at the end are censored at the window end (`window_to_ns`).
- D-311 Messages of types 2-4 that name no tracked order are counted by type in three classes: `after_censoring`, `to_an_excluded_order` (submitted in the window but excluded: no placement, subpenny), and `unknown_id`: submitted before the window, a seed order, or a submission the price-window filter dropped. The estimator cannot tell these three apart, since the lines before `--from` are not observed; the replayer's own `unknown_id` and `seed_attributed` are in `report.replay`.
- D-312 Kaplan-Meier. Event times are the distinct cancellation lifetimes; at a time with both, the censored orders are still at risk (`n_i` counts them), the usual convention. S is the running product of (n_i - d_i) / n_i in doubles, so 3/4 and 3/8 are exact. The whole curve is written with `at_risk` and `events`: one entry per distinct cancellation time, which makes the fake days' files 9 MB (SYNTHA) and 17 MB (SYNTHB); a liquid real day will be larger.
- D-313 Median mid: time-weighted, the lower weighted median of best bid + best ask over the published rows of the window, then floored to ticks (`floor(m / (2 tick))`). A row holds from its message's time to the next observed message's; the row before the first observed message holds from the window start and the last row until the window end. One-sided and missing-row time is reported, not used; a window without two-sided time is an error. Time-weighted rather than per row, because bursts write many rows in one instant.
- D-314 Placement fit (report only). Per side, over the samples with Delta >= 0 of all spread buckets: discrete maximum likelihood of `(delta0 + Delta)^-(1 + mu) / Z` on Delta = 0..Delta_max, truncated at the largest observed Delta (the filter truncates the data). mu in [-3, 20] by golden-section search for each delta0 (the log-likelihood is concave in mu); delta0 on a log grid of 101 points in [0.01, 1000], refined by golden-section search between the best point's neighbours. Z is summed term by term for Delta below 1,024 and by Euler-Maclaurin (to the third derivative) above, so a stray deep price costs nothing. When mu ends at a bound the report says the PMF is not power-law shaped: on both fake days the noise trader's uniform distance drives delta0 and mu up together, towards an exponential (mu = 20, delta0 about 250). Rejected: least squares on the log PMF, which weights the sparse tail like the bulk and is not a likelihood. Tests: an exact (1 + Delta)^-1.6 PMF gives back delta0 = 1 and mu = 0.6, and an exact (2 + Delta)^-2.5 PMF on 0..2,000 (through the tail formula) delta0 = 2 and mu = 1.5, both to 1e-3.
- D-315 Order-sign autocorrelation (report only): the bursts in event order, +1 for a buy aggressor and -1 for a sell; the sample ACF c_k / c_0 with the mean removed, at lags 1, 10 and 100; null when n <= k or c_0 = 0. The scorecard version belongs to the fingerprint module (C4).
- D-316 Provenance. `source` is `synthetic` when `README_SYNTHETIC.txt` is beside the message file and `real` otherwise; `--source real|synthetic` overrides (the API rejects anything else). The calib fixtures carry a `README_SYNTHETIC.txt` saying they are hand-written. `inputs` are the two file names (never paths) and their SHA-256 (`src/calib/sha256.cpp`, FIPS 180-4; the four standard test vectors are tested). `code_commit` comes from a header generated at every build by `cmake/git_commit.cmake` and rewritten only when its text changes: `git rev-parse HEAD`, with `-dirty` appended when tracked files have uncommitted changes, `unknown` without git (configure time alone would go stale after a commit). Ticker, date and L come from the file names through the new `replay::parse_lobster_filename` (the ticker is everything before `_<DATE>_`, underscores allowed); the two names must agree on L.
- D-317 The report and the API. `report` holds `observed` (lines, first and last line, first and last message time, what stopped the replay, the bound line), `window` (requested bounds, the data's first message, the last one read, whether the data goes past the end), `messages` by type, `tick`, `placement` (samples, exclusions, fit notes), `sizes`, `aggressive`, `lifetime` (every counter above), `lifetime_median_ns`, `median_mid`, `sign_autocorrelation`, `replay` (the replayer's counters for lines 1..N), `known_bias` and `warnings`. `calib::estimate_files(messages, orderbook, EstimateOptions)` and `calib::estimate(istream, istream, InputInfo, EstimateOptions)` (seekable streams: the message stream is read twice) return an `EstimateResult`: the `Calibration` (validated), the warnings, the observed message time range `first_message_ns`/`last_message_ns` (the earliest and latest message time handed to the estimator, for the leakage test), and with `keep_lifetimes` one `LifetimeRecord` per tracked order (end, end line, lifetime). Errors: `EstimateError` (input that cannot be estimated), `replay::InputError`, `std::invalid_argument` (options).
- D-318 `lobsim_calibrate` dispatches on a table of subcommands (name, usage, function); `validate` is one more row. `estimate` writes `<out>/<stem>.json` with `calib::save` (which validates) and `<stem>.md` beside it; `--out` defaults to `calibration/`. Exit codes: 0, 1 (bad arguments, a file name that is not a LOBSTER name, input that cannot be estimated), 3 (a `--messages` or `--orderbook` path does not exist, checked before anything else). The fake days' outputs are not committed: they are synthetic, reproducible with one command each, and 9-17 MB. Tests: `calib_estimator_tests` (both worked examples of section 1.3 exactly, censoring at the right row and none with fewer than L levels, pre-window exclusion and both window bounds, the tick rule with its warning and subpenny, bursts, nearest-rank pooling, the median mid, the fit, the ACF, round trip through `save`/`load`, the source rule, SHA-256, file names, and the hook), and ctest `calibrate_cli` (exit codes 0, 1, 3, the files and their labels). Each check was broken on purpose once (17 mutations: Delta from the row after, an execution as an event, censored-at-t not at risk, `<=` against the L-th level, the row before for censoring, a bound from an empty L-th level, observing from 0, a message at `--to` replayed, the first pass or the replay reader going on past the bound line, the tick and warning rules, subpenny, per-message bursts, the aggressor side, rank n, per-row median) and a test failed each time.
- D-319 The fake days (SYNTHETIC data, D-227; whole span 34200.0017-37799.98 s, tick 1, L = 10; release build, 1.3 s and 2.5 s including hashing). SYNTHA: lambda_L 23.79 buy and 23.67 sell per s, lambda_M 4.25 and 4.20; median mid 9,984 ticks. SYNTHB: 47.43 and 47.27, 10.30 and 8.88; 10,016 ticks. Against `configs/default.json`: the noise traders alone submit 10 x 5 x 0.85 = 42.5 limit and 7.5 market orders per second; the market maker's quotes add about 5 limit orders per second (47.5 measured) and the informed trader's orders, sent only past its threshold, about 1 aggressive order per second (8.45 measured). SYNTHB doubles the noise rate and quadruples the informed one: 85 + about 10 limit and 15 + 4 aggressive per second, as measured. Placement: with s = 2 (83% of samples) Delta is roughly uniform on 0..9 (Delta = d - 1 for the noise trader's d ~ U[1, 10]), with extra mass at 0 and 1 from the market maker's quotes; at s >= 3, -1 and 0 take 60% (mid +- 1 rounded into the spread); the largest Delta is 9 or 10 (D = 10), so the power-law fit hits its bound (D-314). Sizes: 1..10 near 9% each and 5 near 20% (the market maker's and informed trader's size 5); aggressive 5 at 27%. Lifetimes: the 3-9 bucket's KM median is 20.81 s (SYNTHA) and 20.83 s (SYNTHB), against 30 s x ln 2 = 20.79 s for the noise trader's exponential; the buckets at the touch are shorter (9.1-9.9 s at Delta <= 0, 15.3-15.9 s at 1-2), most likely because the market maker's quotes, requoted every 100 ms, sit there (not measured per owner: the files carry no owner), and orders there are censored by execution far more often (64% at Delta <= 0). 16% of the 3-9 orders left the window (17,161 in SYNTHA), and 8,897 deletes came after a censoring. Sign autocorrelation about 0.03-0.05 (SYNTHA) and 0.09 (SYNTHB) at lags 1, 10 and 100: the informed trader trades in one direction while the mispricing lasts, so the four-times-stronger informed flow of SYNTHB shows twice the memory; the noise traders' signs are independent.

## Calibration (upgrade 3), C2: calibrated background flow
- D-320 Calibration file I/O (`src/calib/calibration.cpp`, static library `calibfile`, not built under `LOBSIM_FUZZ`; tests `calib_tests`). The JSON keys follow the struct members; per-side arrays are objects `{"buy", "sell"}`, spread and distance buckets are objects keyed by `spread_bucket_name`/`distance_bucket_name`, a Pmf is `{"values", "counts"}`, an absent `placement_fit` entry is `null`, `report` is passed through unchanged. `from_json` rejects unknown keys, missing keys (all but `report`, which defaults to `{}`), values of the wrong JSON type (including a negative number where an unsigned one is expected) and then calls `validate`; every error names the field path. `save` validates, then writes `dump(2)` and a newline. `Calibration` gained `operator==` (defaulted, additive) so a round trip can be tested. Two rules beyond the header: placement values are bounded below by -(s-1) only in the buckets `1` and `2`, and `placement_fit` numbers must be finite. Empty Pmfs and empty survival curves are valid files; the agent decides what it needs.
- D-321 Distances: both normalise by the totals (as doubles of the counts), total variation merges the two sorted supports, and W1 sums |F_P - F_Q| times the gap to the next support point (F is constant between support points), so a gap of many ticks costs one multiplication.
- D-322 Config: the optional `background` section is `{"model": "calibrated", "file", "owner_count" (default 50), "latency_us" (default all 0), "start_price" (default the calibration's `median_mid_ticks`)}`; unknown keys are an error. `parse_config(j, base_dir = "")` resolves a relative `file` against `base_dir`; `load_config` passes the config file's directory (so the result does not depend on the working directory); an empty `base_dir` leaves the path as given. The calibration is loaded and validated inside `parse_config` and held by `shared_ptr` in `BackgroundConfig`. Beyond `validate`, the config refuses a calibration the agent cannot sample from, naming the field: `limit_size` empty with a positive limit rate, `aggressive_size` empty with a positive aggressive rate, any of the three placement PMFs empty for a side with a positive limit rate (every spread bucket is reachable), or every rate 0. Without the section nothing changes: `to_json(cfg)` has no `background` key and the other code paths are untouched.
- D-323 Several owner ids for one agent. `Simulator::set_owner_count(agent, n)` gives an agent its own id (agent index + 1) plus `n - 1` extra ids taken from `kExtraOwnerBase` (2^30) upwards in call order, so no existing agent's id, event order or hash changes. A request keeps its owner if it is one of the sender's ids and otherwise gets the sender's own id, as before. Private events for an extra id go to its agent; a trade between two ids of one agent is delivered once (the agent would otherwise reduce an order twice). `Context` gained `owner_count()`, `owner_id(k)` and `owns(owner)` with defaults that describe one owner, so the existing contexts and agents are unchanged. The exchange log already writes the owner on every line and the LOBSTER export uses order ids, so `lobsim_export_lobster` and the replay work on these runs (tested in `calibrated_flow_closed_loop`). `MetricsObserver` counts ids from `kExtraOwnerBase` upwards as the noise role (the background), only when the section exists. A cancel carries the owner of the order's placement (a cancel under another of the agent's ids is refused with `NotOwner`, tested).
- D-324 `CalibratedFlowAgent` runs after every other configured agent (after the market maker), so no existing agent's index changes. It has its own `StreamRole::CalibratedFlow` (4, appended). Streams: decisions from `ctx.rng()`, lifetimes from a separate (role, 0, Lifetimes) stream, one `uniform01` per limit-order ack. Orders cycle through the owner ids (limit and market orders share one counter). Sides use the measured probabilities as a double compared with `uniform01()`. Delta is drawn from a cumulative `uint64` table (`uniform_int(0, total - 1)` plus binary search; totals above 2^63 use raw rejection sampling). The lifetime is the smallest `times_ns[i]` with `survival[i] <= u` (a binary search by comparisons); `u` below the last value, or an empty curve, schedules no cancel; the lifetime is capped at `kFarFutureNs`.
- D-325 Empty and one-sided local books (the spec leaves the bucket and the crossing bound open). Two-sided: bucket from s = ask - bid, Delta >= -(s - 1). Own-side best present, other side absent: the reference is the own best, the bucket is `3+` and nothing is checked for crossing (there is nothing to cross). Own-side best absent, other side present: the reference is the other best -/+ 1 tick, which makes a virtual spread of 1: bucket `1`, bound 0. Empty book: the reference is the start price, bucket `1`, bound 0. The first two are counted as `fallback_one_sided`, the third as `fallback_empty`. A price outside [1, max_price] is moved to it and counted (`price_clamped`); a Delta beyond 2 * max_price is limited first so no integer overflows.
- D-326 `lobsim_run` prints `background ...` lines (orders sent against the configured rates, redraws, clamps, fallbacks, cancels scheduled, no-cancel draws and sent) only when the section is present. End-to-end check on `tests/fixtures/calib/flow_small_run.json` (hand-made calibration, no other agent, 60 s, seed 7, rates 8 limit and 1 aggressive per second): 460 limit and 70 market orders (expected 480 and 60), 801 requests, 101 trades, exported with `lobsim_export_lobster` and replayed with `lobsim_lobster`: strict mode at compare depth 10 completes, and in resync mode all 832 rows are exact before any correction, with 0 corrections, 0 removals and every skip counter 0; with `--lobster-like --window-start-s 10`, 756/756 rows exact, 10 hidden executions and 1 halt counted. Test `calibrated_flow_closed_loop` repeats it. These numbers are from a hand-made calibration (synthetic), not from market data.

## Calibration (upgrade 3), C4: market fingerprint
- D-340 One module, `include/calib/fingerprint.hpp` + `src/calib/fingerprint*.cpp` (static library `fingerprint`, CLI `lobsim_fingerprint`, tests `fingerprint_tests`), reads a LOBSTER message/orderbook pair through the replay parsers (an empty level is size 0, whatever its price, so real LOBSTER and `--lobster-like` files are read alike) and returns a `Fingerprint`. Estimators are written out in `docs/FINGERPRINT.md`. Malformed lines, a time that goes backwards or differing row counts are errors that name the line, never silent exclusions.
- D-341 Window `[from, to)` in nanoseconds; defaults: `from` = the first message time, `to` = the last message time + 1 ns. Only messages inside count as events. The book in force when the window opens is the row of the last earlier message (carry-in): it supplies time weights, fixed-clock mids and the placement distance of the first window messages. Time before any row exists is counted as `no_state_ns`, not hidden. Fills and executions are observed inside the window only, so orders submitted near its end are right-censored; data and simulation share this effect because they pass through the same code.
- D-342 Time-weighted metrics: the spread PMF (ticks = integer price difference / `tick_units`, floor; rows whose difference is not a whole number of ticks are counted in `off_grid_rows`; crossed rows stay in the PMF and are counted in `crossed_ns`) uses two-sided time only, with weights in ns; one-sided and empty time are reported separately. Mean depth at level 1..L per side divides by the time with a book, empty levels count 0.
- D-343 Volatility is on a fixed clock anchored at `from`: the mid at grid time t is the last row at or before t (rows inside the window and the carry-in), as `ln(ask + bid)` so a return is `ln(S_{j+1} / S_j)`. An interval without a two-sided book at either end is skipped and counted (`skipped`); there are `floor((to - from) / c)` intervals per clock. Std uses n - 1; excess kurtosis uses population moments (m4 / m2^2 - 3).
- D-344 Autocorrelation, for every series (1 s returns, |10 s returns|, trade signs): centre at the mean of the valid entries; `rho_k = (mean of c_i c_{i+k} over the pairs of valid entries) / (mean of c_i^2 over the valid entries)`. The numerator is divided by its own pair count, not n, so a short series is not shrunk towards 0 (this differs from the textbook estimator by n / (n - k)). Lag is in grid steps (returns) or bursts (signs). No pair: undefined (NaN, JSON null).
- D-345 Aggressive orders are bursts (maximal runs of consecutive type 4 messages with the same time and direction); sign = minus the resting side's direction. A type 5, 6 or 7 breaks a run and is never an aggressive order. lambda_M counts bursts by aggressor side; lambda_L counts type 1 messages by side (a market order's resting remainder written as type 1 counts there too, as the exporter and LOBSTER write it).
- D-346 Fills: limit orders are the type 1 messages inside the window; the distance is `(best bid - price) / tick` for a buy and `(price - best ask) / tick` for a sell, from the row before the message, in the buckets of `calib::distance_bucket`. An order is filled if a type 4 message inside the window carries its id; orders with no best price on their side before them go in `placement_unknown` and in the all-orders figures only. A repeated id is counted (`duplicate_order_ids`) and its first submission is kept. Executed share = executed shares of those orders / their submitted shares. (Superseded in part by D-395: an id reused after its order ended starts a new order.)
- D-347 Uncertainty of data: the window is cut into one-second bins; each bin holds additive sufficient statistics (time, depth x time, spread-by-time, order and fill counts, rates) and each series has prefix sums over its own index, so a resample is a handful of range sums, not a pass over the data. Moving-block bootstrap: blocks of 300 bins starting anywhere (overlapping), ceil(N / 300) blocks per resample, 1000 resamples, `Xoshiro256StarStar(seed)` with seed 20120621; the interval is the 2.5 and 97.5 percentiles of the resampled scalars (undefined if fewer than 20 resamples define it). The point estimate is the same code applied to all bins, so the two cannot disagree.
- D-348 Resampling units: time-weighted metrics, order counts and rates: the second. Returns: a block takes the returns whose interval lies inside its seconds (clock c: indices ceil(s / c) to floor(e / c)). Autocorrelation numerators use only pairs inside one block (no pair joins two blocks, so the join is not a fake correlation), centred at the whole-window mean. Bursts and orders attach to the second of their time (a fill to the second of its order's submission); sign autocorrelation pairs are bursts inside one block. A window not longer than one block is degenerate: every resample is the data (flagged, interval of zero width).
- D-349 Runs of a simulation: `combine_runs` gives, per scalar, mean, sd (n - 1), the confidence interval of the mean `mean +- t(0.975, n - 1) sd / sqrt(n)` (`ci_lo`, `ci_hi`), and the run-to-run range (empirical 2.5 and 97.5 percentiles, linear interpolation: `run_lo`, `run_hi`). The verdict of C5 should compare the data interval with the confidence interval, since both are intervals for a typical value; the run range is for display.
- D-350 Distributions: `distances(a, b)` gives W1 (ticks) and TV between spread PMFs and between depth profiles, which become PMFs over the level numbers 1..L with weight round(1000 x mean size) (levels of 0 left out), so W1 is in levels and depth shape is compared, not scale. `Prepared::halves` gives the same distances between the first and second half of the window and, as the yardstick for "how far is too far", the bootstrap mean, se and 2.5/97.5 percentiles of that distance with each half resampled alone (same block length, capped at the half's length). The yardstick is noisy by construction when the halves are short; it is reported as it comes.
- D-351 Exporter `--price-scale N` (default 1) multiplies the price of every message and every real orderbook level by N; placeholders (9999999999, -9999999999, and 0 under `--lobster-like`) and the halt's -1 are not scaled; `--audit` keeps simulator prices. N must be a positive integer and `max_price * N` must stay below 9999999999 so no real price can equal a placeholder (checked from the log header before anything is written). Default output is byte-identical (`lobster_export_fixture`, closed loop and rehearsal unchanged); `lobster_price_scale` checks 100x on the plain, filtered and `--lobster-like` outputs.

## Calibration (upgrade 3), C3: parameter recovery
- D-360 The truth (`calibration/recovery_truth.json`, 131 KB, written by `tools/make_recovery_truth.py`, standard library only, `--check` in ctest `recovery_truth_up_to_date`). Placement (1 + Delta)^-1.6 on 0..30, plus 10% improving: none for s = 1, Delta = -1 for s = 2, uniform on -1..-4 for s >= 3. Lifetimes S(t) = 0.3 1[t < 0.5 s] + 0.7 e^(-t/20 s) in every distance bucket, on a grid of 50 ms to 5 s (a point exactly at the 0.5 s jump), 10 ms to 9 s, 50 ms to 20 s, 0.5 s to 100 s, 5 s to 400 s, then S = 0 at 600 s. A lifetime is the first grid time with S <= u, so it is rounded up by at most one step; the median on the grid is 6.730 s against the exact 20 ln(1.4) = 6.7294 s (+0.008%). Weights are counts floor(p 10^9 + 0.5). Rates 20 and 2 per second and side, `median_mid_ticks` 10000. Arrays of numbers are written on one line to keep the file small.
- D-361 Sizes (free in the specification) were chosen after looking at the simulated market. With aggressive orders sized like limit orders (mean 217 shares) the price never moved: in 20 minutes every sample fell in the s = 1 bucket. Six aggressive-size distributions were tried in 20-minute runs, looking at the spread and at the samples per spread bucket; the one kept (mean 972: 100 15%, 500 20%, 1000 30%, 2000 15%, 5000 5%, odd lots 15%) is the first with all three buckets filled and a median spread of 1 tick (90th percentile 4). ## Security and performance review (outside the upgrades)

- D-900 A review of `main` (bbb0bbb) treated every file a tool reads and every command-line argument as attacker-controlled, and timed every tool on the default 1-hour run. clang-tidy 23 (`bugprone-*`, `cert-*`, `clang-analyzer-*`, `performance-*`) found no memory-safety defect. Its two analyzer reports are false positives: the division in `CumulativeTable::sample` cannot see 0, because the constructor rejects a zero count, and the "uninitialized" values in `stats::mean` come from a span the caller fills. Fixed: D-901 to D-913. Every change keeps every output byte the same. 51 output files were compared: `lobsim_run` on three seeds with its stdout, two viz bundles (one forced through the budget loop), three LOBSTER exports and nine replay summaries. They are identical before and after.
- D-901 Command-line numbers that are scaled are range-checked before the multiplication, so they can neither overflow (undefined behaviour) nor wrap to 0. In `lobsim_viz_export`, the millisecond steps go up to INT64_MAX / 10^6, `--budget-mb` up to INT64_MAX / 2^20, `--levels` up to 10,000 and `--heatmap-pad-ticks` up to 10^9. In `lobsim_fingerprint`, `--from-s` and `--to-s` go up to INT64_MAX / 10^9, and `--resamples` and `--block-s` up to INT_MAX, which they used to wrap: `--resamples 4294967301` meant 5.

Measured: 0.84 s to 0.50 s on the 1-hour run.
- D-908 The viz exporter finds the market maker's quotes from the ids acked to it, instead of copying every level's orders on every ladder sample. Every order reaches the book through an Ack, so those ids cover all of the MM's resting orders; ids whose order is gone are dropped when found. The quotes are a max and a min, so the order of the ids does not matter. The book snapshot behind the heatmap is a reused vector of (price, size) instead of a new `std::map` per request. Each price appears once, because the book never crosses, and each pair is added into its own cell, so the sums are the same bit for bit.
- D-909 Fixes a high-severity hang in the viz exporter. `lobsim_viz_export` sampled the ladder every `--ladder-dt-ms` across the whole time range before checking anything, so one far-off timestamp in `orders.log` made it loop and allocate without bound: two requests at 0 and 9 x 10^18 ns ran until killed. It now replays once without sampling, then verifies the hash, the trades and the PnL. Next it fits the budget by arithmetic, and only then samples, once. The counts the budget loop needs follow from the time range alone: ladder samples = (last - first) / dt + 1, heatmap columns = (last - 1 - first) / dt + 1 when last > first, else 0. So the doubling decisions are the old ones exactly, computed in saturating integer arithmetic. The sampling pass checks that it made exactly those counts and fails otherwise. Behaviour changes only where the old code was undefined or hung. A run whose last time is 2^53 ns or more, or whose step would overflow, now fails at once with exit 2 instead of later. A run that no sampling fits (prices spanning more rows than the budget has bytes) now exits 2 instead of writing an over-budget bundle after 64 doublings; the old loop overflowed its step after 36. The default export also no longer replays the log a second time. Measured: 1.90 s to 0.39 s on the 1-hour run.
- D-910 `pages.yml`, the only workflow with write access (`pages: write`, `id-token: write`), pins its four actions to commit SHAs with the release in a comment: checkout v7.0.1, configure-pages v6.0.0, upload-pages-artifact v5.0.0, deploy-pages v5.0.1. Each SHA was resolved through the GitHub API and equals the major tag it replaces. A moved tag can no longer change what publishes the site. `.github/dependabot.yml` keeps the pins current. The deploy job runs only on `refs/heads/main`, so a manual run from another branch builds but does not publish. `ci.yml` and `fuzz-nightly.yml` keep their tags: their token is read-only and they use no secrets, and changing their `uses:` lines would conflict with the open feed branch.
- D-911 `scripts/run_recovery.sh` accepts only digits for `--window-s` and `--seed`. The window went into `$(( ))`, where bash runs command substitutions: `--window-s 'a[$(cmd)]'` ran `cmd`. Because the script deletes fixed names under `--out`, it now refuses an output folder holding anything it does not write itself, which includes `/`. `tests/calibrate_cli.cmake` quotes `${OUT}` in `REMOVE_RECURSE` and fails on an empty `OUT`. `tests/lobster_audit_test.py` deletes its work folder only when it is named `lobster_audit_self_test`, the name ctest passes. `DASHBOARD.md` and `web/README.md` start `http.server` with `--bind 127.0.0.1`, so local runs are not served to the network.
- D-912 The replayer keeps its last 20 message lines in a ring of reused strings and formats "line N: text" only for a strict-failure report or a burst example. It used to build one string per line. `parse_book_line` reads the fields in one pass instead of splitting them into a temporary vector; the fields are parsed and checked in the same order, so every error message is unchanged. ## Pre-sized order-id index (side task)

- D-260 `lob::BookConfig` has a new field `std::size_t expected_order_ids{0}`. When it is above 0, `OrderBook`'s constructor sizes the order-id index for ids 1 to `expected_order_ids`, so no message pays for a doubling while ids stay within the estimate. 0, the default, keeps the old behaviour: the index grows on demand. Ids beyond the estimate still grow it through the same doubling in `rest()`, so a low estimate is never wrong, only slower. `ReferenceBook` ignores the field. The defaulted `operator==` compares it too. Only `lobsim_bench` sets it, to the message count, which bounds the ids because each message is at most one new order. The simulator, replay, exporters and tests keep 0: their runs have far fewer orders, and pre-sizing costs 8 bytes per expected id (80 MB for the benchmark's 10,000,000 messages).
- D-261 The constructor calls `index_.resize(expected_order_ids + 1, nullptr)`, not `reserve`. `rest()` tests `t.id >= index_.size()` and grows the index with `resize`, which needs the slots to exist. After a `reserve` the size would still be 0: the first new order would resize, which writes every new slot and triggers the doubling the field exists to avoid. With `resize`, the slots exist and are null, the state `validate()` expects for ids that are not resting. Slot 0 is never used, because ids start at 1.
